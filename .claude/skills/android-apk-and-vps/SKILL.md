# Выпуск APK и эксплуатация VPS

GramMarket использует один APK для обоих игроков. Backend на FastAPI, SQLite, Ollama и Caddy рассчитан на Debian 13 с 1 vCPU и 2 ГБ RAM. Проверяй репозиторий и локальную сборку. Операции на сервере выполняй только по отдельной явной задаче. При установке этого навыка сервер не меняй.

## Android и CI

1. Проверь Gradle Wrapper, совместимую с Android Gradle Plugin версию JDK, Android SDK и имена модулей и вариантов. Установи воспроизводимые версии. Определи реальные задачи через `./gradlew tasks --all`. Запусти задачи сборки debug, unit-тесты и lint для модуля приложения. Для проверок на устройстве используй [android-emulator-qa](../android-emulator-qa/SKILL.md).
2. Передавай адрес API через свойство Gradle, переменную CI или существующий механизм конфигурации вариантов. Для release требуй валидный HTTPS URL и явную ошибку сборки, если адрес отсутствует. Проверь итоговый вариант. URL — конфигурация сборки. Секреты авторизации хранятся на сервере или в защищённых настройках и в APK не включаются.
3. В GitHub Actions используй закреплённые версии инструментов, Gradle Wrapper и права только для нужных операций. Отдели проверки PR от подписывания релиза в доверенном окружении. Передавай keystore и пароли из защищённого хранилища CI, создавай временный файл на runner, удаляй его после сборки, исключай вывод значений и загрузку файла в артефакты.
4. Для обновления сохраняй прежний `applicationId` и тот же ключ подписи, увеличивай `versionCode`. Проверь подпись и отпечаток через `apksigner verify --print-certs`. Проверь установку предыдущего APK и обновление через `adb install -r` на тестовом устройстве с сохранением данных. Публикуй как артефакт подписанный APK и его SHA-256. Резервную копию ключа храни вне Git с контролем доступа.

## Backend на Debian 13

- На сервере Caddy обслуживает публичный HTTPS, FastAPI слушает loopback, Ollama доступна для backend только по loopback или локальному приватному каналу. Привяжи persistent SQLite к каталогу данных сервиса. Файлы окружения, ключи и пароли размещай вне Git, с доступом для нужного сервисного пользователя.
- Для запуска используй существующие systemd units и конфигурацию проекта. Проверь синтаксис конфигурации Caddy, состояние сервисов, журналы и ответ существующего health endpoint через HTTPS. Проведи smoke-тест двух тестовых клиентов с обменом репликами и одной генерацией Ollama. Запиши HTTP-статусы и ошибки без данных пользователей.
- Начни с одного worker FastAPI и одного выполняющегося задания Ollama. Выбирай квантованную модель по измерениям RSS, контекстного окна и задержки на этом VPS. Проверь поведение под двумя одновременными клиентами и тайм-аут. Не обещай работоспособность модели без измерений.
- Для согласованного бэкапа работающей SQLite используй Online Backup API или команду `sqlite3` `.backup`. Сохраняй ограниченный набор копий вне VPS с доступом только для оператора. Проверь `PRAGMA integrity_check` на копии и восстановление в отдельный временный каталог. Перед миграцией сделай проверенный бэкап. В ходе проверки используй копию базы для пробного восстановления.
