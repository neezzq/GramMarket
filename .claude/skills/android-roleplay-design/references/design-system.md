# Дизайн-система GramMarket

Интерфейс строится вокруг тёмных нейтральных поверхностей и одного янтарного акцента. Иллюстрации задают настроение истории на обложке и помогают узнавать персонажей в диалоге. Используй оригинальные или явно лицензированные изображения. Для сторонних ассетов фиксируй автора, источник и условия использования. Для текста поверх обложки проверь контраст на самом светлом участке или вынеси подпись на отдельную поверхность.

## Токены Material 3

| Токен | Значение и применение |
| --- | --- |
| `background` / `onBackground` | `#121214` / `#F0EEF0` для основы экрана |
| `surface` / `onSurface` | `#1A1A1E` / `#F0EEF0` для карточек, диалогов и форм |
| `surfaceContainerHigh` / `onSurfaceVariant` | `#2A2A30` / `#C9C6CF` для приподнятых областей и вторичного текста |
| `primary` / `onPrimary` | `#F4BB68` / `#2B1900` для основных действий и фокуса |
| `primaryContainer` / `onPrimaryContainer` | `#473218` / `#FFE2B9` для выбранного элемента и реплики игрока |
| `outline` / `outlineVariant` | `#98939E` / `#49464F` для границы поля и декоративных разделителей соответственно |
| `error` / `onError` | `#FFB4AB` / `#690005` для ошибок. Дополняй цвет видимым текстом или значком с подписью |

- **Типографика.** Используй системный `FontFamily.SansSerif` с кириллицей. Для `headlineSmall` — 24/32 sp, `titleMedium` — 16/24 sp, `bodyLarge` для реплик и повествования — 16/24 sp, `bodyMedium` — 14/20 sp, `labelLarge` — 14/20 sp. Для выделения действий используй настоящий курсив. Используй масштабируемый текст, перенос слов и гибкую высоту компонентов. Длинные сцены, сообщения об ошибках и подписи действий должны полностью читаться при увеличенном шрифте.
- **Отступы.** Шкала 4, 8, 12, 16, 24, 32 dp. Для компактного экрана начни с 16 dp по краям, 12 dp внутри карточки и 8 dp между сообщениями. На широкой компоновке ограничь основную колонку сцены примерно 640 dp и сохрани место для переноса строк.
- **Скругления.** 8 dp для небольших элементов, 12 dp для полей и реплик, 16 dp для обложек и 24 dp для верхних углов панели редактора. Аватар круглый.
- **Состояния.** Используй стандартный Material 3 ripple. Фокус показывай контуром `primary`, выбранное состояние — парой `primaryContainer` / `onPrimaryContainer` и соответствующей семантикой. Для отключённых действий используй штатные disabled-цвета. Для ожидания сообщай, какая операция выполняется. Проверяй контраст итоговых цветов с учётом фона, прозрачности и наложений. Цели касания — от 48 × 48 dp.

## Компоненты

В таблице приведены данные и события для проектирования API компонента. Согласуй типы и именование с моделями проекта и выноси состояние, которым управляет экран.

| Компонент | Входы и действия | Состояния |
| --- | --- | --- |
| `StoryCard` | ID, заголовок, обложка, краткая подпись последней сцены, `onOpen` | Заглушка, загрузка изображения, обложка, резервное изображение при ошибке, выбранная история на широком экране |
| `CharacterAvatar` | Имя, источник портрета, размер, при необходимости `onClick` | Портрет, инициалы при загрузке или ошибке, семантика кнопки для интерактивного варианта. При видимом имени у декоративного аватара `contentDescription = null` |
| `DialogueBubble` | ID сообщения, роль, имя, аватар, сегменты текста и состояние доставки, `onRetry` | Реплика игрока или ИИ-персонажа, отправка, принята, ошибка отправки. Имя, положение и тон поверхности помогают различить авторов |
| `NarrationBlock` | Сегменты повествования, состояние генерации, при необходимости `onRetry` | Готовый текст, частичный ответ, ошибка. Отдельная подпись «Рассказчик» и широкая область чтения |
| `SceneComposer` | Черновик, доступность отправки, статус связи, `onDraftChange`, `onSend` | Пусто, ввод, отправка, нет связи, восстановление. Кнопку видно над IME, черновик переживает временную ошибку |
| `FriendRequestRow` | ID заявки, ник, направление и статус, `onAccept`, `onDecline` | Новая входящая, выполнение действия, обработанная заявка, ошибка. Действия привязаны к строке, под длинным ником помещаются в отдельном ряду |
| `CharacterEditorSheet` | Редактируемая карточка, ошибки полей, признак изменений, статус сохранения, `onFieldChange`, `onSave`, `onDismissRequest` | Чистая форма, правки, сохранение, ошибка, подтверждение выхода с изменениями. На широком окне можно показать форму в панели |

## Экраны и поведение

- **Регистрация.** Одно поле «Ник» и кнопка «Продолжить». Покажи правило в supporting text и ошибку рядом с полем, включая занятой ник. При сетевом сбое оставь введённое значение. Согласуй валидацию с сервером.
- **Истории.** Покажи обложки и названия, выдели доступное действие «Продолжить» для последней сцены и «Новая история» для создания. Для пустого списка оставь прямой переход к созданию.
- **Друзья.** Поле «Точный ник» и запуск поиска. Рядом с найденным профилем покажи «Добавить» или статус заявки. В блоке входящих заявок помести «Принять» и «Отклонить» в соответствующей строке. Предусмотри результаты «Ник не найден», ожидание, пустые заявки и ошибку запроса.
- **Чат.** Используй `LazyColumn` со стабильными ID. Для игроков и ИИ-персонажей покажи имя и аватар, для рассказчика — отдельный блок. Отобрази сегменты `*действий*` курсивом, а реплики — обычным начертанием через `AnnotatedString`. Верхняя панель открывает карточку персонажа. Если читатель у конца списка, показывай новые реплики по мере поступления. Если читатель выше, сохраняй якорь и смещение и показывай кнопку «Новые сообщения».
- **Редактор персонажа.** Разбей поля на короткие группы «Основное», «Характер» и «Привычки». При ошибке сохраняй правки. После успешного сохранения верни пользователя в ту же сцену с прежней позицией. Подтверждай выход при несохранённых правках только после Back, закрытия или другого действия выхода.
- **Статусы сцены.** Различай «Отправляется», «ИИ пишет», «Нет связи», ошибку сообщения и ошибку генерации. Помести «Повторить» рядом с неудавшейся операцией. В `Scaffold` учитывай системные отступы и IME один раз, держи композер видимым и не теряй фокус при поступлении реплик.
